## 1. Назначение проекта

**fc-racks** — демонстрационный фронтенд-прототип, показывающий, как может выглядеть
функционал **создания стеллажей и их распределения по складу**.

Задача, которую решает интерфейс: дать пользователю понятный и наглядный способ описать
структуру склада — от зданий до отдельных ячеек на полках — и получить на выходе
**структурированные данные (JSON)**, которые:

- можно передать на бэкенд;
- можно загрузить обратно и **полностью восстановить** из них интерфейс и визуальное представление склада.

Проект делается быстро, «на показ»: он нужен, чтобы продемонстрировать подход и сравнить
несколько вариантов интерфейса, а не как production-решение.

Цели проекта:

1. **Создание** — несколько вариантов интерфейса для настройки стеллажей и их расстановки.
2. **Сохранение** — данные в едином формате JSON.
3. **Восстановление и просмотр** — визуальное представление склада, построенное из этих данных.

## 2. Ограничения и требования к реализации

| Требование | Как выполнено |
|---|---|
| Только фронтенд, без сервера и серверного рендеринга | SPA на React + Vite, чистый клиентский рендеринг |
| Данные хранятся на клиенте | `localStorage` браузера (Zustand + `persist`) |
| Сборка и публикация на GitHub Pages | `base: '/fc-racks/'` в Vite, `HashRouter`, деплой через GitHub Actions |
| Визуальный, «красивый» интерфейс, а не просто формы | Стеллажи, полки и ячейки нарисованы схематично (div + CSS), с кнопками «+ / −» и drag & drop |
| Данные на выходе — JSON для бэкенда | Экспорт/импорт JSON с валидацией по схеме |

## 3. Предметная область

### 3.1. Иерархия

```
Здание
└── Этаж                (1, 2, 3 и больше)
    └── Ряд             (1, 2, 3 и больше на каждом этаже)
        └── Стеллаж     (1, 2, 3, 4, 5 и больше в каждом ряду; тип задаётся шаблоном)
            └── Полка   (1, 2, 3, 4 и больше — по высоте стеллажа)
                └── Ячейка  (1, 2, 3, 4, 5 и больше — своё количество на каждой полке)
```

### 3.2. Сущности

**Здание** — склад верхнего уровня («Здание 1», «Здание 2», «Здание 3»). Складов может быть несколько.

**Этаж** — уровень внутри здания. В здании может быть один, два, три и больше этажей,
и у разных зданий их число может различаться.

**Ряд** — линия, вдоль которой расставляются стеллажи. Стеллажи на этаже ставятся
**только по рядам**. На каждом этаже может быть свой набор рядов.

**Стеллаж** — конструкция с полками. В каждом ряду может стоять разное количество
стеллажей, и стеллажи в одном ряду могут быть **разных типов**. Например:

- на первом ряду — 4 стеллажа;
- на втором ряду — ещё 4;
- на ряду другого этажа — 5 стеллажей.

**Полка** — горизонтальный уровень стеллажа. Количество полок — это высота стеллажа
в «этажах хранения».

**Ячейка** (коробка) — место на полке, куда ставится товар. Главная особенность:
**на каждой полке может быть своё число ячеек**.

### 3.3. Примеры стеллажей из ТЗ

**Стеллаж с тремя полками:**

```
 ┌───────────────────────────┐
 │  [  ▢  ]  [  ▢  ]         │  верхняя полка — 2 ячейки
 ├───────────────────────────┤
 │  [ ▢ ]  [ ▢ ]  [ ▢ ]      │  средняя полка — 3 ячейки
 ├───────────────────────────┤
 │  [▢]  [▢]  [▢]  [▢]       │  нижняя полка  — 4 ячейки
 └───────────────────────────┘
```

**Стеллаж с пятью полками:** на трёх нижних полках по 3 ячейки, на двух верхних — по 2.

```
 │ [ ▢ ] [ ▢ ]       │  полка 5 — 2 ячейки
 │ [ ▢ ] [ ▢ ]       │  полка 4 — 2 ячейки
 │ [▢] [▢] [▢]       │  полка 3 — 3 ячейки
 │ [▢] [▢] [▢]       │  полка 2 — 3 ячейки
 │ [▢] [▢] [▢]       │  полка 1 — 3 ячейки
```

Комбинации могут быть любыми: количество зданий, этажей, рядов, стеллажей, полок и ячеек
задаётся независимо на каждом уровне.

## 4. Ключевая идея: два конфигуратора

Работа разделена на два независимых этапа:

1. **Конфигуратор шаблонов стеллажей.** Пользователь заранее описывает *типы* стеллажей:
   «Тип A — 3 полки, 4/3/2 ячейки», «Тип B — 5 полок, 3/3/3/2/2 ячейки» и т. д.
2. **Конфигуратор расстановки.** Пользователь создаёт здания, задаёт этажи, на каждом этаже —
   ряды, и **расставляет в рядах стеллажи выбранных типов**: «в этом ряду A, A, B, B»,
   «в другом — C, D».

Почему так удобнее:

- шаблон описывается один раз и переиспользуется сотни раз;
- изменение шаблона автоматически применяется ко всем стеллажам этого типа;
- расстановка сводится к выбору типа, а не к повторной настройке полок и ячеек;
- JSON остаётся компактным: стеллаж в ряду хранит только ссылку на шаблон.

## 5. Варианты интерфейса

На обсуждении были предложены несколько вариантов для каждого этапа, чтобы сравнить их
на одних и тех же данных.

### 5.1. Конструктор шаблонов

| Код | Вариант | Суть |
|---|---|---|
| **A1** | Визуальный конструктор | Стеллаж нарисован «фасадом»: стойки, полки, ячейки-коробки. «+» внутри полки добавляет ячейку; у каждой полки — число ячеек, сдвиг вверх/вниз, копия, удаление; «+ полка сверху / снизу» |
| **A2** | Форма-таблица с превью | Таблица «полка → количество ячеек» со степперами, рядом — живое превью стеллажа |
| **A3** | Быстрое создание | Пресеты («3 × 3», «Пирамида», «5 × 4»…) и формула `4-3-2`; встроено в A1 |

### 5.2. Расстановка

| Код | Вариант | Суть |
|---|---|---|
| **B1** | Дерево + план этажа | Слева дерево зданий/этажей, в центре план этажа с рядами, справа палитра шаблонов. Стеллажи добавляются «+» или перетаскиванием, переставляются drag & drop |
| **B2** | Мастер массовой генерации | Пошагово: здания → этажи → ряды → состав рядов → итог. Быстрый старт для большого склада |
| **B3** | Табличный редактор | Одна таблица «Здание · Этаж · Ряд · Состав», состав ряда — чипы шаблонов |

### 5.3. Просмотр

| Код | Вариант | Суть |
|---|---|---|
| **V1** | Drill-down просмотр | Здания → этажи → план этажа → фасад ряда → карточка стеллажа с адресами ячеек |
| **V2** | Изометрия / 3D | Объёмный вид склада. Отложен как возможное развитие |

## 6. Принятые решения

| Вопрос | Решение |
|---|---|
| Какие варианты реализовать | Все: **A1 + A3, A2, B1, B2, B3, V1** и страница JSON |
| Как ставить стеллажи в ряд в B1 | **И клик («+» с выбором шаблона), и drag & drop** (из палитры, внутри ряда и между рядами) |
| Учитывать ли физические размеры (длина ряда, ширина стеллажа, площадь этажа) | **Нет**, только количества — схематичное представление |
| Ширина ячеек на полке | **Одинаковая**: ячейки делят полку поровну, хранится только их количество |
| Удаление шаблона, который уже расставлен | **Запрещено**, пока его стеллажи стоят в рядах |
| Хранение выбора между страницами | Выбранный шаблон/этаж хранится в URL (`?id=`, `?b=&f=`), чтобы переключение вариантов не сбрасывало контекст |
| Стартовое состояние | При первом открытии загружается **демо-склад**, чтобы сразу было что показать |

## 7. Модель данных (JSON)

### 7.1. Структура

```json
{
  "version": 1,
  "rackTemplates": [
    {
      "id": "tpl_a",
      "name": "Тип A · пирамида",
      "color": "#3b82f6",
      "shelves": [
        { "id": "sh_1", "cells": 4 },
        { "id": "sh_2", "cells": 3 },
        { "id": "sh_3", "cells": 2 }
      ]
    }
  ],
  "buildings": [
    {
      "id": "bld_1",
      "name": "Здание 1",
      "floors": [
        {
          "id": "fl_1",
          "name": "Этаж 1",
          "rows": [
            {
              "id": "row_1",
              "name": "Ряд 1",
              "racks": [
                { "id": "rk_1", "templateId": "tpl_a" },
                { "id": "rk_2", "templateId": "tpl_a" }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

### 7.2. Правила

- `version` — версия формата, нужна для будущих миграций.
- **Полки перечисляются снизу вверх**: `shelves[0]` — нижняя полка.
- `cells` — целое число от 1 до 50; ячейки на полке одинаковой ширины.
- У стеллажа минимум одна полка.
- Стеллаж в ряду (`racks[]`) — экземпляр шаблона: хранит свой `id` и `templateId`.
- **Порядок элементов в массивах значим**: этажи — снизу вверх, ряды — по порядку на этаже,
  стеллажи — слева направо в ряду.
- Каждый `templateId` обязан ссылаться на существующий шаблон из `rackTemplates`.
- Все сущности имеют `id`, что позволяет бэкенду сопоставлять объекты при повторной загрузке.

Схема описана на [zod](https://zod.dev) в `src/domain/schema.ts`; TypeScript-типы выводятся из неё же.

## 8. Адресация ячеек

Адрес каждой ячейки вычисляется из её позиции в иерархии (нумерация с единицы):

```
З1-Э2-Р3-С4-П2-Я1
│  │  │  │  │  └─ ячейка на полке (слева направо)
│  │  │  │  └──── полка (снизу вверх)
│  │  │  └─────── стеллаж в ряду (слева направо)
│  │  └────────── ряд на этаже
│  └───────────── этаж
└──────────────── здание
```

Адрес не хранится в JSON, а вычисляется: при перестановке стеллажей адреса пересчитываются
автоматически. В интерфейсе адрес виден при наведении на ячейку и в карточке стеллажа.

## 9. Сохранение, экспорт и восстановление

- **Автосохранение.** Любое изменение сразу сохраняется в `localStorage`
  (ключ `fc-racks`); после перезагрузки страницы всё на месте.
- **Экспорт.** На странице JSON данные можно скопировать или скачать файлом `fc-racks.json`.
- **Развёрнутый вид.** Дополнительно выгружается плоский список всех ячеек с адресами
  (`fc-racks-cells.json`): здание, этаж, ряд, стеллаж, шаблон, номер полки и ячейки.
  Он только для чтения — удобен для бэкенда/WMS.
- **Импорт.** JSON вставляется в поле или загружается файлом, проверяется по схеме
  (включая ссылки на шаблоны). При ошибках показывается список проблем с путями,
  текущие данные не меняются. После подтверждения данные заменяются, и весь интерфейс
  восстанавливается из JSON.
- **Демо и сброс.** Кнопки в шапке загружают демо-склад или очищают все данные.

## 10. Страницы приложения

Все страницы работают с одним хранилищем — любой вариант можно сравнить на одних и тех же данных.

| Маршрут | Раздел | Вариант | Что на странице |
|---|---|---|---|
| `#/templates` | Шаблоны · Визуально | A1 + A3 | Список шаблонов, конструктор фасада, параметры (имя, цвет, статистика), пресеты и формула |
| `#/templates/form` | Шаблоны · Форма | A2 | Таблица полок со степперами, «всем полкам по N», превью |
| `#/layout` | Расстановка · План | B1 | Дерево зданий/этажей, план этажа, палитра, drag & drop, заполнение и дублирование рядов, карточка стеллажа |
| `#/layout/wizard` | Расстановка · Мастер | B2 | Пошаговая генерация, общий и пообъектный состав рядов, режим «заменить / добавить» |
| `#/layout/table` | Расстановка · Таблица | B3 | Таблица с группировкой по зданиям и этажам, чипы стеллажей, фильтр по зданию |
| `#/view/…` | Результат · Просмотр | V1 | Здания → здание → план этажа → фасад ряда; хлебные крошки, легенда шаблонов |
| `#/json` | Результат · JSON | — | Экспорт, развёрнутый список ячеек, импорт с валидацией |

## 11. Технический стек и структура

**Стек:** React 19, TypeScript, Vite, Tailwind CSS v4, shadcn/ui, Zustand (`persist` + `immer`),
`@dnd-kit` (drag & drop), zod (валидация), react-router (`HashRouter`), sonner (уведомления).

```
src/
├── domain/                 предметная логика без UI
│   ├── schema.ts           zod-схема формата данных
│   ├── types.ts            типы, выведенные из схемы
│   ├── address.ts          адреса ячеек, статистика, развёрнутый список ячеек
│   └── demo.ts             демо-склад
├── store/
│   └── useWarehouseStore.ts  хранилище и все операции над данными
├── components/
│   ├── rack/               RackFacade (фасад стеллажа), RackBlock, RackDialog, TemplatePicker
│   ├── templates/          список шаблонов, параметры, пресеты
│   ├── layout/             редактор состава ряда
│   └── ui/                 компоненты shadcn/ui
├── pages/                  страницы A1, A2, B1, B2, B3, V1, JSON
└── App.tsx                 роутинг
```

Центральный визуальный элемент — `RackFacade`: один компонент рисует стеллаж
в четырёх размерах (от иконки в списке до большого редактора) и используется во всех вариантах.

## 12. Сборка и публикация

```bash
npm install
npm run dev       # http://localhost:5173/fc-racks/
npm run build     # сборка в dist/
npm run preview   # просмотр собранной версии
```

Публикация: при каждом push в `main` GitHub Actions собирает проект и выкладывает его
на GitHub Pages (`.github/workflows/deploy.yml`). В настройках репозитория должно быть
включено Settings → Pages → Source: **GitHub Actions**.

## 13. Что можно развить дальше

- **3D / изометрический просмотр склада** (вариант V2).
- **Физические размеры:** ширина стеллажей, длина рядов, площадь этажа и проверка вместимости.
- **Ячейки разной ширины** на одной полке.
- **Двусторонние ряды** и проходы между рядами на плане.
- **Латинская адресация** (`B1-F2-R3-S4-L2-C1`), если кириллическая «З» путается с цифрой 3.
- **Интеграция с бэкендом:** отправка JSON по API вместо `localStorage`, миграции по полю `version`.
- **Наполнение ячеек товарами** и отображение заполненности склада.
